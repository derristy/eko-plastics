# Уровень 2 — Обновление цен и XML-фид

Два скрипта: `update-prices.php` подтягивает цены из прайса в файл импорта, `generate-xml.php` делает из результата XML-фид для маркетплейсов.

```
composer install
php update-prices.php
php generate-xml.php
```

Результаты складываются в `output/`: `import-updated.xlsx` и `feed.xml`.

## Как сопоставляются позиции

Прямой связи между файлами нет — артикулы в импорте и прайсе из разных систем (`woks17k-110` против `922001`), совпадений ноль. Поэтому позиции матчатся по модели и числовому параметру: из названия вытаскивается модель (`Woks-10`, `DTIR-150`), а параметр берётся из названия и из колонок импорта с длиной, мощностью и площадью. Ключ вида `woks10|m:100` ищется в прайсе.

Матч засчитывается, только когда модель и параметр совпали полностью, и когда по ключу в прайсе одна цена. Сначала я пробовал матчить ещё и по одному бренду без номера модели, но так Woks-17 цеплялся к ценам Woks-18 и Woks-10 — для цен это недопустимо, поэтому такой вариант убран.

Параметр из названия имеет приоритет над колонками, и это не перестраховка. В выгрузке попадаются строки с чужими характеристиками: у мата `DTIR-150-1.5` в колонке площади стоит `3,5 м.кв`, а длина `7 м` — значения от мата на 3,5 м². Если верить колонке, товар получает цену другой позиции, 11024 вместо 6859. В названии площадь указана правильно, поэтому сначала разбирается оно.

Обновлённым позициям цена ставится из прайса, старая цена считается как цена + 10%. Строки заливаются цветом: жёлтым те, где цена изменилась, зелёным те, где она совпала с прайсом.

## Про количество совпадений

На текущих файлах обновляется 17 позиций и ещё 15 совпадают по цене — из 2059 товаров. Это не ошибка сопоставления, а свойство данных: прайс закрывает лишь часть ассортимента. Общих моделей у файлов всего 10 из 335, а, например, Woks-17 в прайсе представлен единственной позицией 8,5 м с пометкой «остатки, снят с производства», тогда как в импорте таких товаров 18.

## Объёмы

`generate-xml.php` читает xlsx потоком через `XMLReader` и пишет фид через `XMLWriter`, поэтому память не зависит от размера файла. На 12 354 строках — 5 секунд и 2 МБ памяти, на 2060 строках — 0.4 секунды.

Изначально чанки в генераторе были сделаны через `ReadFilter` PhpSpreadsheet, но там каждый чанк заново разбирает весь файл, и на 12 тысячах строк это не укладывалось и в две минуты. Отсюда собственный потоковый ридер в `src/XlsxRows.php`.

`update-prices.php` использует PhpSpreadsheet, потому что для заливки строк цветом нужна полноценная работа со стилями. Файл импорта читается чанками по 500 строк, но книга целиком остаётся в памяти: на 12 тысячах строк это порядка 312 МБ, так что для больших объёмов нужен `memory_limit` от 512 МБ.
