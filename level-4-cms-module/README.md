# Уровень 4 — Сниппет для MODX

Форма обратной связи для MODX 3: серверная валидация, защита от спама, сохранение заявок через xPDO и передача их в SalesDrive.

Демо: https://eko-plastics-modx.derristy.com/contact.html

Вариант C из задания. Выбрал MODX, потому что файл `Import.xlsx` из второго уровня — выгрузка MODX (колонки `tv.*` это Template Variables), то есть магазин заказчика работает именно на нём.

## Установка

Скопировать `core/components/ekoform` в `core/components` сайта, положить `install.php` в корень и выполнить:

```
php install.php
```

Скрипт генерирует классы модели из схемы, создаёт таблицу `ekoform_leads`, регистрирует namespace, сниппет `ekoForm`, чанк `ekoFormTpl` и две системные настройки. Дальше в любом ресурсе достаточно вызвать:

```
[[!ekoForm]]
```

Вызов некэшируемый — со восклицательным знаком, иначе форма не будет обрабатывать POST.

В системных настройках нужно заполнить `ekoform.api_key` — ключ из раздела API в кабинете SalesDrive. Адрес по умолчанию лежит в `ekoform.api_url`. Если ключ пустой, заявки сохраняются локально со статусом `skipped`, а в лог пишется предупреждение.

## Параметры сниппета

`&tpl` — чанк с разметкой формы, по умолчанию `ekoFormTpl`.
`&successTpl` — чанк, который показывается вместо формы после успешной отправки, по умолчанию пусто.
`&minSeconds` — сколько секунд минимум человек заполняет форму, по умолчанию 3.

## Валидация и защита от спама

Имя и фамилия — только буквы, апостроф и дефис, проверка юникодная, так что «Іван» и «О'Коннор» проходят. Телефон нормализуется: `067...` превращается в `+38067...`, затем проверяется по списку кодов украинских операторов. Email проверяется, если заполнен. Все проверки серверные.

Капчи нет. Вместо неё скрытое поле `company`, которое заполняют только боты, и отметка времени открытия формы — отправка быстрее трёх секунд отклоняется. Обе ситуации пишутся в лог MODX с уровнем WARN.

## Хранение

Модель описана схемой `model/schema/ekoform.mysql.schema.xml`, классы генерируются xPDO-генератором при установке. Заявка сохраняется в `ekoform_leads` до обращения к CRM, поэтому не теряется, даже если SalesDrive недоступен. В таблице остаётся статус передачи (`pending`, `sent`, `failed`, `skipped`), номер заказа и текст ошибки.

Если CRM не ответила, пользователь всё равно видит подтверждение: заявка уже у нас, а разбираться с ошибкой — задача администратора, для этого её текст и пишется в `crm_error` и в лог.

## Передача в SalesDrive

Запрос уходит на `/handler/` с ключом в заголовке `X-Api-Key`. В `externalId` пишется `modx-<id>`, чтобы заявку можно было сопоставить с записью в таблице. Из ответа сохраняется `orderId`.

## Что учтено из «буде перевагою»

xPDO для хранения, логирование через `modx->log` на всех ветках, мультиязычность через лексиконы (`uk` и `ru`) и интеграция с CRM. Кеширование не делал: тут нечего кешировать, справочников компонент не тянет.
